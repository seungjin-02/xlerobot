# LeKiwi Control Center — Phase 1 분석·구현

**현재 상태:** 사용자가 2026-10-15 원본을 Public으로 전환했습니다. 아래 공개 배포 비교는 최초 설계 당시의 판단 기록입니다. 현재 출처·포털은 [PUBLICATION.md](PUBLICATION.md), 제공된 개발 지시서 기준 추적은 [REQUIREMENTS.md](REQUIREMENTS.md)를 따릅니다.

## 화면 전환과 안전 의미

내부 메뉴 전환은 기존 lease로 더 큰 seq의 idle 명령을 보낸 뒤 화면을 전환합니다. 확인 응답이 없으면 조종 종료를 요청하고 현재 화면에 남습니다. 기록과 제어권은 정상 전환에서 유지합니다. 기록 화면에서 새 주행은 조종 화면으로 돌아가 명시적으로 선택합니다. 항상 보이는 정지 버튼과 기록 종료 버튼은 조종을 종료합니다.

브라우저 hidden/pagehide/blur는 제어권을 폐기하고 stop을 요청합니다. 지연된 arm 응답도 화면이 비활성화됐거나 generation이 바뀌면 수용하지 않고 stop을 재요청합니다. stop 실패 경고는 일반 안내 문구로 덮어쓰지 않습니다.

브라우저가 종료되거나 통신이 끊기면 stop/beacon 전달을 보장할 수 없습니다. 기존 10초 유예가 적용될 수 있습니다. 드라이버 timeout 300ms는 웹 서버가 계속 마지막 출력을 발행하는 동안의 10초 유예를 대체하지 않습니다. 실제 제동 거리·물리적 정지·모터 전원 상태는 현장에서 검증해야 합니다. 유예 단축은 사용자 경험과 통신 품질에 영향을 주므로 별도 요구·실물 검증 후 결정합니다.

## 새 읽기 전용 API

- `GET /api/system`: 세션 필요. Git exact tag/HEAD/추적 파일 변경, OS/아키텍처/ROS 환경, systemd show, 웹 응답, 앱 소유 ROS 프로세스, 피드백 최신 여부, 제어권, 기록 경로·공간·오류. 정적 진단은 최대 5초 캐시.
- `GET /api/camera/demo.jpg`: 세션 필요, 데모 전용 합성 JPEG. 실물에서는 404.
- 기존 `/api/status`는 기존 필드를 유지하며 `storage`, recording `elapsed_s`, camera `simulated` 필드를 추가합니다.
- 셸 명령 실행·설정 변경·업데이트 API는 추가하지 않습니다. 외부 프로세스의 정상 여부를 앱 소유 프로세스 상태로 추정하지 않습니다. 모터 상태 미수신은 null/확인 불가, 데모는 시뮬레이션으로 표시합니다.

시스템 정보에는 PIN·Wi-Fi 암호·세션 토큰·Git 원격 인증 URL·개인키를 포함하지 않습니다. 기존 카메라 8080 서버는 PIN 인증 없이 로컬 영상을 제공합니다. 이번 변경에서 인증 모델을 바꾸지 않았으므로 신뢰하는 AP 안에서 운영하고 포트포워딩하지 마세요.

## 공개 배포 결정 — 아직 실행하지 않음

2026-10-15 GitHub 조회에서 원본은 Private, 원격에 릴리스 태그가 없었습니다. 실제 검증 릴리스가 생기기 전까지 설치 도우미는 운영 설치 가능한 버전을 임의로 만들지 않습니다. 예시 v1.0.0을 실존 버전처럼 표시하지 않습니다.

| 선택 | 장점 | 고려 사항 |
| --- | --- | --- |
| 원본을 승인 후 Public 전환 | 단일 이슈/PR/태그·동기화 부담 최소 | 전체 과거 이력·장비 식별 정보·팀 코드까지 공개되므로 권한·이력 감사 필요 |
| 원본 Private, 별도 공개 배포 Git | 공개 대상을 승인된 소스·릴리스로 한정 | 공개 저장소 생성/복제 승인, 릴리스 동기화·원본 추적·도우미 출처 상수/사이트 링크 변경 필요 |

현재 권장안은 **별도 공개 배포 저장소**를 승인 후 마련하는 것입니다. 과거 인수인계 문서와 evidence 등 장비 정보가 포함된 원본 이력의 노출 범위를 줄일 수 있습니다. 원본 공개가 팀 정책상 허용되고 전체 이력 감사가 끝나면 단일 저장소도 가능합니다. 어느 것도 이번 작업에서 공개 전환·원격 변경·원격 복제·게시하지 않았습니다.

공개 전에는 전체 Git 이력의 인증 정보·장비 식별 정보·데이터/스크린샷, 외부 코드 출처/Apache-2.0 고지(`drivers/SOURCE.md`, `drivers/LICENSE`, `LICENSE-NOTICE.md`), 팀 코드 공개 권한을 검토해야 합니다. 현재 `LICENSE-NOTICE.md`는 프로젝트 앱/문서에 추가 공개 라이선스를 부여하지 않는다고 명시하므로, 공개 배포의 사용·재배포 허용 조건도 소유자와 결정해야 합니다. 현재 파일 검사나 HTTPS 인증 성공이 이 감사와 권한 승인을 대신하지 않습니다.

`site/`만 GitHub Pages 업로드 대상으로 지정한 수동 workflow를 제공합니다. 승인 후 해당 저장소의 Pages 사용 가능 요금제/공개 정책을 확인하고 Settings→Pages→GitHub Actions를 구성한 뒤 수동 실행합니다. Private 저장소라고 Pages 페이지도 비공개라고 가정하지 마세요. 배포는 실행하지 않았으며 공개 URL은 아직 없습니다. 포털은 현재 Private/릴리스 미등록 상태를 명시합니다. 배포 출처가 결정되면 링크와 이 안내를 갱신하세요.

## Phase 2 설계 (미구현)

일반 PIN 사용자와 업데이트 관리자 권한을 분리하고, 앱과 별도 계정/권한의 업데이트 실행 서비스가 고정된 작업만 수락하도록 설계합니다. 웹에서 임의 셸·URL·경로를 전달하지 않습니다. 신뢰된 저장소·서명된 릴리스 메타데이터/태그·검증된 서명자 키를 고정하고 commit/checksum을 확인합니다. SHA 대조는 출처를 인증하는 서명을 대체하지 않습니다.

업데이트 승인 → 조종/기록/저장 종료 확인 → 업데이트 잠금과 신규 arm 거부 → 설정·데이터·서비스·구환경 백업 → 별도 릴리스/의존성/ROS 빌드 준비 → 원자적 전환 → 서비스/카메라/센서 검증 → 결과 기록 순서가 필요합니다. 실패 시 Git뿐 아니라 설정 스키마·의존성·유닛·ROS 빌드를 함께 복구합니다. 부팅 실패와 전원 단절도 포함한 실물 테스트 후에만 자동 실행 기능을 제공합니다.
