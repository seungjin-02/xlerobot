최신 main `e9c020f` 기준 `feature/slam-recording`에 추가한 검토용 변경은 [SLAM_HANDOFF.md](SLAM_HANDOFF.md), [SLAM_IMPLEMENTATION_REPORT.md](SLAM_IMPLEMENTATION_REPORT.md)를 확인하세요. 사용자 요청에 따라 로컬 커밋만 남기며 main 병합/원격 푸시를 하지 않습니다. 실물과 연결하지 않았고 모든 새 ROS 지도·목표 추종 증거는 합성 센서·가상 모터입니다. 나중에 Ubuntu 로컬 Codex에서 실물 설정을 확인하고 검토·병합·배포해야 합니다.

최신 작업은 feature/lekiwi-control-center 브랜치입니다. [설계·공개 배포 검토](CONTROL_CENTER.md), [Git 최초 설치](GIT_INSTALL.md), [수동 업데이트·복구](UPDATE.md), [새 검증 범위](VERIFICATION.md)를 먼저 확인하세요. 조종/기록/시스템 UI·PC SSH 도우미·정적 포털을 추가했으며 새 실물 설치나 공개 배포는 수행하지 않았습니다. 아래 2026-10-14 장비 기록은 과거 이력이며 이번 변경의 배포/실물 검증을 뜻하지 않습니다.

## 현재 상태

첫 로봇에는 기존 설치, 두 번째 LeKiwi-b82479에는 최신 카메라 선택 버전이 적용됐습니다. 현재 접근 가능한 로봇은 두 번째이며 기존 로그인 계정은 roboseasy, 유선 IP10.42.0.141(고정 아님). 서버8090, 카메라8080, AP192.168.4.1. 비밀번호는 기기 관리자에게 별도로 받아야 합니다. 기기 설정과 QR은 로봇에만 저장됩니다.

2026-10-14 현재 접근한 두 번째 로봇의 lekiwi-recordings 폴더는 아직 없었습니다. 첫 기기의 이전16MB 기록은 현재 기기와 별개이며 이 저장소에 백업되지 않았습니다. 합성예제는 실제 주행 데이터가 아닙니다.

## 다음 작업 순서

1. GitHub 소스 다운로드, docs/COMPUTERS.md에 따라 SSH와 연결 확인.

5. 학습용 변환과 통계 확인. 팔 정책과 혼합하지 않고 base-only 입출력에 맞는 학습 코드를 별도로 선정/개발.

## 미완료/보류

실물 기록 시작→주행→종료→LeRobot 변환 전체 과정, 실제 모델 학습/평가, 아이폰 실기기, Windows/WSL2 실기기, 새 OS에서 apt부터 시작하는 완전설치, USB 빠짐/재연결의 장시간 실기기시험은 미완료입니다. APK/PWA 오프라인 UI와 스토어 배포는 보류입니다. 팔 제어·팔 데이터셋·팔 모델은 없음.

## 개발 시 지켜야 할 기존 결정

기기별 모터 ticks 제한과 드라이버timeout/torque-off를 유지. 알려지지 않은 다른 driver process는 조종 거부. 저장코드는 제어루프를 막지 않아야 함. 본체 영상이 없다고 집게 영상으로 대체하지 않음. 요청/발행/피드백 속도를 구분. 새 구성을 검증하지 않고 기존 실물 검증으로 간주하지 않음.
