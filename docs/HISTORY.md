# 활동 기록 — 2026-10-13~14

이 문서는 대화의 결정과 보존된 소스·검증 결과를 기반으로 정리한 활동 기록입니다. 원본 대화의 모든 메시지/도구 로그를 그대로 보관한 기록은 아닙니다.

1. 목표: 가까운 거리에서 안드로이드 폰으로 LeKiwi 원격 주행. 노트북과 로봇 무선 연결을 논의한 뒤, 최종적으로 로봇 AP와 로봇 내 서버로 노트북 없이 폰 직결 사용.
2. 기존 로컬 작업에서 모터 제어 경험 확인. 웹 UI·ROS 연결·카메라·사용자 서비스 설치.
3. 속도: 최초 실사용 제한 .03m/s 기준 하한1배/기본10배/상한30배(.03/.30/.90). 회전은 절반 요청에서 사용자 요청으로10배 증가해 이동 숫자5배로 변경(.15~4.5rad/s). 실제 모터 한도를 보존하고 최종 발행 명령을 제한.
4. 접속 코드4자리 지원과 예시1119. 실제 인증 파일과 Wi-Fi 암호는 별도 보관.
5. 조종 방식: 누르는 동안 주행에서 토글 버튼으로 변경. 동일 버튼 다시 누르면 정지, 다른 방향은 부드럽게 연결.
6. 연결 단절: 사용자 결정으로 최대10초 기존 이동 유지. 그 사이 폰 정지 요청이 전달되지 않는 점 안내. 재연결과 timeout 처리 적용.
7. AP 접속: 폰 핫스팟과 모바일 데이터가 켜져 있을 때 접속 실패. 끄고 로봇 Wi-Fi에 연결하니 해결됐다는 사용자 확인. 인터넷 없음은 로봇 직접 연결에서 정상.
8. 카메라 연결 장애 대응, 카메라 자동 시작 서비스와 JPEG 캡처 timestamp 지원.
9. 교체 가능한 기기: 각 지원 기기에 최초1회 설치, 기기 프로필·USB·AP·QR 생성. 미준비 임의 기기의 무설치 조종은 지원하지 않음.
10. 학습 기록: 작업명→조종 시작→기록 시작→시범→성공/실패/미완료 저장·정지. 본체 영상·요청/발행 명령·상태를 저장하고 LeRobot0.6 형식 변환. 학습/자동 주행은 별도 단계.
11. 메모리/저장 확인: 첫 기기29GB 중20GB 여유, RAM7.6Gi 중7.0Gi 사용가능, 기록16MB. 시점 수치이며 현재 값이 아님.
12. 두 번째 기기 랜선 연결: 처음 carrier0, 전원 켠 후10.42.0.141 발견. Ubuntu24.04/ROSJazzy, 여유13GB. 별도 드라이버 빌드1분34초; 기존 실패 반복 lekiwi-host 중지. 설치기 NM 우선순위1000 오류를999로 수정. LeKiwi-b82479 AP, 코드/카메라/웹 정상 확인; 사용자가 '잘 작동하네'라고 주행 확인.
13. 팔과 카메라: /dev/video0가 집게라는 사용자 관찰. 팔 제어를 주행 학습에 섞지 않기로 결정. 본체/집게 화면 선택, 기록은 본체만. 기기별 has_arm/cameras 설정, 포트 기반 카메라 식별과 프레임 신선도 검사를 추가. 현재 두 카메라640x480 수신 확인.
14. 오프라인 화면/APK/PWA/스토어 배포 논의. 구현은 보류. 현재 브라우저 사용에는 로봇 연결이 필요. 로봇 내Ubuntu/ROS와 관리 PC OS를 구분; Windows 관리 안내 준비.
15. 재현/인수인계를 위해 seungjin-02/xlerobot 비공개 저장소 생성. 코드·설치ZIP·문서·검증증거·합성예제를 저장. 실물 데이터와 인증정보는 별도 관리.
