# LeKiwi 폰 조종 · 기기별 설치 · 학습용 기록

**최신 진입점:** [Git 기반 최초 설치와 PC 도우미](GIT_INSTALL.md). 검증된 태그와 전체 커밋을 선택한 Git 체크아웃에서 아래 기존 설치기를 실행합니다. 기존 설치는 [수동 업데이트](UPDATE.md)를 따릅니다. 이 문서 아래의 과거 실물 검증 결과는 이번 Control Center UI/도우미의 새 실물 검증을 뜻하지 않습니다.

각 르키위에 한 번 설치하면, 이후에는 폰에서 그 기기의 Wi-Fi QR을 읽고 조종 화면을 열어 사용할 수 있습니다. 노트북·랜선·인터넷은 평소 조종에 필요하지 않습니다. 최초 시스템 설치에는 관리자 권한과 인터넷이 필요합니다.

지원 범위: 라즈베리파이의 **Ubuntu 24.04, ROS 2 Jazzy, NetworkManager, STS3215 바퀴 ID 7·8·9**. 바퀴 순서는 기기별 프로필로 지정하며 세 ID의 순열을 지원합니다. Raspberry Pi OS나 다른 ROS 버전의 자동 설치는 지원하지 않습니다. 준비되지 않은 임의의 르키위가 폰 연결만으로 작동하는 방식은 아닙니다.

## 새 르키위에 최초 설치

1. SSH로 새 Raspberry Pi에 접속해 Git clone과 검증된 릴리스 태그/커밋 대조를 수행합니다. 새 ZIP 설치 경로는 제공하지 않습니다.
2. 그 기기의 바퀴 번호·순서·회전 방향·바퀴 반지름·중심 거리를 확인합니다. 확인된 ROS 프로필이 있으면 다음처럼 실행합니다.

```bash
cd ~/xlerobot
bash install.sh --profile /path/to/verified-robot-profile.yaml
```

이미 설치된 프로필이 있으면 자동으로 후보로 사용합니다. 없다면 `profiles/standard-sts3215.yaml`이 예시로 선택됩니다. **예시가 해당 기기의 실제 바퀴 순서와 방향을 보장하지 않습니다.** 프로필을 수정하거나 설치 안내에 따라 확인해야 합니다. 안정적인 `/dev/serial/by-id/...` 모터 USB 경로를 찾고, 여러 USB가 있으면 사용자가 선택합니다. 라이다 포트와 혼동하지 않습니다.

3. 설치기는 ROS 의존성을 준비하고 포함된 바퀴 제어 패키지를 빌드합니다. 앱·카메라의 자동 시작과 기기별 Wi-Fi AP를 설정합니다. 기존 `lekiwi-host.service`, `lekiwi-nav.service`는 중지·자동 시작 해제하여 모터 제어 충돌을 막습니다. 기존 서비스 파일은 삭제하지 않고 상태를 기록합니다.
4. `~/.config/lekiwi-phone/connection-card/index.html`과 두 SVG를 PC로 복사해 연결 카드를 인쇄하거나 화면에 띄웁니다.
5. 최초 1회 재부팅합니다. 새 그룹 권한과 AP 설정이 적용됩니다. 설치 자체는 모터를 켜지 않습니다.

새 기기의 기본 Wi-Fi 이름은 무선 MAC 주소에서 만든 `LeKiwi-xxxxxx`입니다. 기기별 암호를 생성하고 QR에 넣습니다. 기본 앱 접속 코드는 `1119`이며 `--pin`으로 4~8자리 숫자를 지정할 수 있습니다. 현재 사용 중인 기기는 기존 `lekiwi01` 이름과 암호를 유지했습니다.

## 폰에서 사용

1. 연결 카드의 **Wi-Fi QR**을 읽습니다. 인터넷 없이 연결 유지 안내가 나오면 유지합니다.
2. **조종 QR**을 읽거나 `http://192.168.4.1:8090`을 엽니다.
3. 접속 코드를 입력하고 `조종 시작`을 누릅니다.
4. 방향 버튼 한 번으로 이동을 켜고, 같은 버튼을 다시 누르면 정지합니다. 다른 버튼으로 부드럽게 전환합니다.

접속이 안 되면 폰의 핫스팟·모바일 데이터를 잠시 끄고 실제로 해당 르키위 Wi-Fi에 연결되어 있는지 확인합니다. 준비가 끝난 로봇은 노트북 전원이 꺼져 있어도 사용할 수 있습니다. 갤럭시와 아이폰의 브라우저를 대상으로 만들었지만 실제 아이폰은 검증하지 않았습니다.

이동 요청은 1배 0.03m/s, 기본 10배 0.30m/s, 상한 30배 0.90m/s입니다. 회전 요청(rad/s)은 이동 요청(m/s)의 숫자 5배이며 기본 1.5rad/s, 상한 4.5rad/s입니다. **기기별 모터 출력 한도에 따라 실제로 전달되는 명령은 더 작아질 수 있습니다.** 설치기는 기존 출력 제한을 보존하며 최대 3000 ticks/s까지만 허용합니다.

연결이 끊기면 마지막 출력을 최대 10초 유지하고 추가로 가속하지 않습니다. 10초 안에 재연결되면 현재 버튼 상태를 반영하고, 그 이후에는 정지·토크 해제를 요청합니다. 서버 출력 자체가 중단되면 바퀴 노드의 300ms timeout이 적용됩니다. 통신 장애 중에는 폰의 정지 요청도 전달되지 않을 수 있습니다.

## 앱에서 학습용 데이터 수집

1. 작업 이름을 입력합니다. 예: `박스 옆에 주차한 뒤 출발점으로 복귀`.
2. `조종 시작` → `기록 시작`을 누릅니다.
3. 폰으로 시범을 수행합니다.
4. `성공으로 저장 · 정지`, `실패로 저장 · 정지`, 또는 `기록 종료 · 정지`를 선택합니다.
5. 저장 목록의 `다운로드`로 기록 ZIP을 받습니다. PC에서 폴더를 직접 복사해도 됩니다.

파일은 라즈베리파이의 `~/lekiwi-recordings/<episode-id>/`에 저장됩니다. 버튼을 누르기 전에는 기록하지 않으며 클라우드에 자동 업로드하지 않습니다.

- `episode.json`: 작업 이름, 결과, 기기·바퀴·카메라 설정, 프레임 수, 완료 여부.
- `samples.jsonl`: 초당 20개를 목표로 카메라 시각·로봇 상태·요청 명령·출력 제한 후 전달 명령을 기록.
- `commands.jsonl`: 폰에서 받은 방향/속도 명령과 시각.
- `frames/*.jpg`: 전방 카메라 프레임.

영상의 캡처 시각과 상태 수신 시각은 같은 라즈베리파이의 monotonic clock을 사용합니다. 기록은 최신 영상을 상태와 연결하는 방식이며 하드웨어 트리거로 완벽하게 동기화된 센서 측정은 아닙니다. 영상이 150ms보다 오래되거나 상태가 250ms보다 오래된 구간, 연결이 끊겨 마지막 명령을 유지하는 구간은 `training_valid=false`로 남겨 변환 시 제외합니다. 바퀴 상태는 엔코더 기반 상대 odometry이며 지도 기준 위치는 아닙니다.

실제 물리 속도를 요청값과 같다고 가정하지 않습니다. `requested_action`은 폰의 요청, `applied_action`은 출력 제한과 부드러운 전환 후 발행한 명령, `state`의 속도는 바퀴 피드백에서 추정한 값입니다. 정상 기록 종료 시 정지 후 약 0.3초의 관측도 저장합니다. 예기치 않게 종료되거나 저장 공간이 부족하면 중단된 기록으로 표시합니다.

## LeRobot 학습 형식으로 변환

PC에 기록 ZIP을 풀고 LeRobot 0.6.x 환경에서 실행합니다. 새 PC 환경 구성은 DATA.md를 참고하세요.

```bash
source ~/lekiwi-training/.venv/bin/activate
python export_lerobot.py /path/to/recordings --output /path/to/new-dataset --repo-id local/lekiwi-base-demos
```

기본값은 완료된 성공 기록만 변환합니다. 실패를 포함하려면 `--include-failures`, 미분류·중단 결과를 포함하려면 `--include-unfinished`를 지정합니다. 불완전 파일, 오래된 센서·통신 단절 구간은 제외하고, 최소 10프레임의 유효 연속 구간을 20fps로 재배치합니다. 해상도가 다른 영상은 별도 데이터셋으로 변환합니다.

변환 데이터는 전방 이미지, 6차원 상태(x, y, yaw, vx, vy, yaw rate), 3차원 행동(vx, vy, yaw rate)입니다. 학습 대상 행동은 실제 발행한 명령이며 요청 명령도 별도 보존합니다. LeRobotDataset로 저장하고 `source-recordings.json`에 원본 기기와 구간을 남깁니다. 기존 팔 포함 9차원 정책에 그대로 넣는 데이터는 아닙니다. 주행용 정책을 학습·평가해야 하며 기록만으로 모델이 자동으로 학습되거나 성공이 보장되지 않습니다. 업로드는 하지 않습니다.

## 관리자 옵션과 복구

- `--serial-port /dev/serial/by-id/...`: 자동 검출 대신 모터 USB를 지정.
- `--camera 0 --camera-rotation 0`: 카메라와 방향 지정. 안정적인 `/dev/v4l/by-path/...`도 가능.
- `--name 이름 --ssid Wi-Fi이름 --pin 1119`: 연결 카드 정보 지정.
- `--workspace /path/to/known-ros-workspace --skip-dependencies`: 이미 준비된 호환 ROS 환경 재사용.
- `--activate-ap`: 설치 마지막에 AP를 바로 활성화. 현재 무선 SSH가 끊길 수 있으므로 유선 설치에서 사용하는 것이 좋습니다.
- `--dry-run`: 프로필/선택 정보를 확인하고 실제 변경 없이 종료.

설정은 `~/.config/lekiwi-phone/`에 저장합니다. 이전 프로필은 `robot-profile.previous.yaml`, 이전 사용자 서비스 파일은 `.service.previous`, 기존 제어 서비스의 enable 상태는 `previous-controllers.json`에 남습니다. 기존 firmware·LeRobot·ROS workspace를 삭제하지 않습니다. 모터 방향을 확인하지 않은 기기에 다른 로봇의 프로필을 그대로 복사하지 않습니다.

```bash
systemctl --user status lekiwi-phone.service lekiwi-camera.service
journalctl --user -u lekiwi-phone.service -n 50 --no-pager
```

## 포함된 소스와 검증 범위

ROS 바퀴 제어는 `roboseasy/lekiwi` 커밋 `ae27af1b94e1febea0caa2563d53751f16f38063`의 `lekiwi_node`를 포함합니다. Apache-2.0 라이선스는 `../drivers/LICENSE`에 있습니다. ROS 설치 절차는 [공식 Jazzy 설치 문서](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html)를 따릅니다.

- Python 제어·설치·기록·변환 테스트 47개 통과.
- 포함한 C++ 바퀴 패키지 빌드와 테스트 결과 190개, 오류/실패 0.
- HTTP 기록 시작·종료·정지·인증된 ZIP 다운로드 검증.
- 합성 시범 77프레임을 실제 LeRobotDataset로 변환하고 이미지·상태·행동을 다시 읽음.
- 폰 크기 화면에서 기록 버튼과 저장 목록을 확인.
- 현재 르키위에 기록 UI와 캡처 시각을 포함한 카메라 서비스를 설치, 실제 카메라 JPEG 수신 확인.

2026-10-14 두 번째 실물에 설치했고 사용자가 주행이 잘 작동한다고 확인했습니다. 코드에서 모터를 활성화하거나 실물 주행 시범을 자동 수집하지는 않았습니다. 새 OS에서의 전체 apt 설치와 실제 아이폰도 별도 검증이 필요합니다. 현재 장비에는 모터 활성화나 이동 명령을 보내지 않고 설치했습니다.

## 본체·집게 카메라 구분

설치 시 `--camera /dev/v4l/by-path/...-video-index0`로 본체 카메라를 지정합니다. 팔 장착 기기는 `--has-arm --wrist-camera /dev/v4l/by-path/...-video-index0`도 지정하세요. 동일한 USB 카메라가 같은 식별자를 쓰는 경우 USB 포트 경로로 구분하므로 케이블을 같은 포트에 연결해야 합니다. 역할은 설치 때 실제 영상을 보고 확인해야 합니다.

웹 화면은 기기 설정의 팔 유무와 각 카메라의 실제 프레임 수신 상태를 표시합니다. 집게 카메라를 선택해 봐도 학습용 기록은 본체 영상만 저장하며 팔 제어는 포함하지 않습니다. 본체 카메라가 없으면 집게 영상으로 대체하지 않고 기록 시작을 거부합니다. 이전에 집게 영상을 전방 영상으로 기록한 데이터는 새 본체 데이터와 섞기 전에 확인해야 합니다.
